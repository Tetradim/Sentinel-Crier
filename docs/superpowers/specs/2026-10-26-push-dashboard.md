# Phase L — push delivery and observational copy dashboard

The user approved the dashboard described in conversation (#4) and immediate server push. Implement directly on main under standing approval; no PR/worktree and no real broker orders or Discord messages. The host remains the sole strategy authority. This feature must never submit/cancel/reprice orders from dashboard data or P&L. Execution, broker/ownership/lifecycle fencing, source revision invalidation and durable unknown outcomes remain unchanged.

## Architecture

Use authenticated Server-Sent Events (SSE), supported by the existing HTTP libraries on all clients. `GET /api/sync/stream?after=N` sends complete existing intent pages immediately over an open HTTPS response. Supabase uses private Realtime database broadcasts as wake-ups; a server-only service-role subscriber bridges them to authenticated SSE. Native clients never receive a service-role key, JWT signing secret, or direct access to relay tables. Broadcasts contain hints only, not orders or telemetry. The Edge Function always fetches durable, role-authorized data before delivering it. Local Python relay uses its in-process change notification after committed writes, with durable reads as truth.

Subscribe before the initial durable drain; coalesce wakes without losing a wake during reads. Deliver intent pages before dashboard work; dashboard refresh may coalesce for up to 250 ms but must not throttle order pages. No one-second polling sleep on the normal stream path. Bound buffers/backpressure and close rather than drop silently. Reconnect automatically with the last cursor committed after local acceptance/quarantine; duplicate pages stay idempotent. Never infer permission to replay expired/superseded buys. Heartbeat at most 15 seconds; authenticated revocation is checked on wakes/heartbeat. Rotate Edge streams before Free-plan lifetime (90 seconds), with automatic reconnect and durable catch-up. Slow recovery checks may run on heartbeat; they are a backstop, not the normal delivery trigger. If streaming is unavailable, retain existing bounded long polling and display `poll`, not `push`. No latency SLA is claimed.

Frames are UTF-8 SSE, bounded to 1 MiB per event and a bounded line count. Support `event: ready` with `{"version":1,"transport":"push"}`, `event: events` with exactly the existing `{"events":[{"cursor":N,"event":IntentEventV1}],"cursor":N}` envelope, `event: dashboard` with the snapshot below, and `event: heartbeat` with `{"server_time_ms":number}`. Unknown frame names may be ignored within size limits; malformed known frames fail safely/reconnect. Bearer token stays in request headers, never URLs, logs or exports. `after` uses the existing cursor validation. A host never consumes stream events into its execution engine; only followers ingest remote intents.

## Observational HTTP contract

New protected routes: `POST /api/sync/status`, `POST /api/sync/presence`, `GET /api/sync/dashboard`, `GET /api/sync/stream`. Existing routes remain compatible. Backend authenticates opaque token to channel/role/actor on every operation; body cannot choose actor/channel. Hosts see channel host + authorized receiver reports. A receiver sees host + itself only, and only events after its enrollment cursor. Cross-channel access, revoked tokens and pre-enrollment status writes/reads are denied. Broker credentials, full account IDs, balances and unrelated holdings are never shared. Explain tracked-status sharing in Host/Receive UI; use opaque receiver IDs/aliases.

Presence body (strict keys): `{"version":1,"revision":1,"observed_at":"ISO8601 aware","platform":"windows|android|ios|python","transport":"push|poll|connecting","entries_enabled":false}`. Revision is a durably increasing integer 1..9007199254740991 scoped to the actor/pair. Send on change and every 15 seconds while connected. Backend stores received_at, not client time, for online/stale display. Mark stale after 45 seconds; stale telemetry never means positions closed. Presence has no execution authority.

Status body (strict keys; nullable fields may be omitted and normalize to null):

```json
{"version":1,"event_id":"canonical UUID of this trade's latest local source instruction","revision":1,"observed_at":"aware ISO8601","broker_observed_at":null,"state":"received","target_quantity":null,"bought":0,"sold":0,"buy_premium":null,"sell_premium":null,"currency":null,"multiplier":null,"fees":null,"quote":null,"reason":null}
```

States: received, submitted, working, partially_filled, filled, cancel_pending, canceled, closed, blocked, unknown, not_submitted. Reasons: null, broker_unavailable, reconciliation_required, entries_paused, invalid_instruction, not_submitted, quantity_unavailable, expired, clock_uncertain, client_unavailable. No raw exception strings. Quantities are strict integers bought/sold 0..1000000, sold<=bought, target null or 0..1000. Currency/multiplier are both null or verified USD + stock1/option100 matching the source asset. `buy_premium`/`sell_premium` are exact sums of cumulative broker average fill price × filled units, **before multiplier**; null if any contributing filled order lacks valid evidence. Nonnegative plain decimal strings, <=120 characters / 80 significant digits; positive if filled units positive, zero/null if units zero. Fees null unless complete actual USD fees known; never assume zero. Quote null or existing QuoteObservation shape (source, aware quote_timestamp, optional bid/ask/last decimal strings). Fresh quotes are optional, read-only, bounded and asynchronous; missing entitlements/errors produce unavailable values. Metadata lookup/quote collection must never block order receipt/submission.

Store latest report per channel/trade/actor. Bind event to persisted channel trade; reject decreasing event sequence, bought/sold counters and conflicting reuse of the same report revision. Identical retries are idempotent; stale revisions return 409. Clients persist report revision/outbox per pairing and coalesce newer observational reports, never manufacture new trading events. Send updated reports promptly after local receipt/order state changes, independently of execution. Capture broker_observed_at from actual validated reconciliation, not telemetry heartbeat. Self-reported reconciliation is labeled device-reported; the relay does not independently attest broker data.

Dashboard snapshot:

```json
{"version":1,"channel_id":"UUID","environment":"paper","role":"host","actor":"host","generated_at":"server aware ISO8601","members":[{"actor":"host or receiver UUID","role":"host|follower","revoked":false,"last_seen_at":null,"presence":null}],"events":[],"statuses":[{"actor":"host","received_at":"server timestamp","report":{}}],"diagnostics":[{"event_id":"UUID","actor":"host","observation":{}}],"truncated":false}
```

Events are latest desired **canonical IntentEventV1 per trade**, newest first (limit50). Statuses max200; members max200; diagnostics max200. Correlate statuses to included trades and retain source event identity so a missing source is shown unavailable, not guessed. `truncated` is true if any eligible rows are omitted. Do not claim complete portfolio totals from truncated data. All role/enrollment filtering happens server-side. Dashboard GET accepts no actor/channel selection or trade actions. A rejected telemetry payload never quarantines a valid trading instruction.

## Presentation and calculations

Add native Windows, Android and iOS read-only Copy dashboard. Show role/platform/transport/last-seen, host instruction versus local target/actual bought/sold/remaining, statuses and safe reasons, entry/exit price differences, near-event premium/clock-adjusted delivery estimates where existing diagnostic evidence permits, and row detail. Show data age/offline/unknown clearly. No trading controls, risk filters, auto-stops, autonomous exits, manual retry or automatic catch-up button on this screen. Local search/sorting are display only.

Average prices = premium sum / filled units, explicitly rounded display values (up to8 decimals). Closed-trade gross realized P&L only when bought==sold>0, both sums and verified currency/multiplier known: `(sell_premium - buy_premium)*multiplier`, USD2 half-up. Net only if complete actual fees known. Partially closed realized P&L stays unavailable rather than invent a lot allocation. Open unrealized estimate may use a fresh bid, complete entry cost and verified multiplier; label quote source/as-of and estimate, suppress stale/missing quotes. Aggregated results only include complete closed rows and disclose missing/truncated rows. Source and receiver results are separate; no promise of identical fills/profit. Use shared JSON fixtures for monetary display/unknown/stale cases across clients.

## Client integration

Wake execution on stream receipt immediately after durable accept. Android replace fixed300ms wait with a signal + periodic reconciliation fallback; wake host outbox on newly created instructions instead of relying on100ms scan. iOS use a pending-work signal so receipt during an in-flight process executes again as soon as it finishes rather than waiting2s; keep serialized mutations and actor/lifecycle fences. Python existing changed/publish events remain immediate. Do not parallelize conflicting broker mutations or remove fresh reconciliation to claim speed.

Telemetry/stream failure never stops an otherwise authorized trading path beyond transport being unavailable; durable polling fallback remains. Stop/logout/background cancels streams/reporters and rejects late callbacks by pairing/API/generation. Dashboard cached snapshots are scoped to pairing and cleared on disconnect/account change; retained audit reports are not current health. All new streams/queues close on shutdown, no busy loops or leaked watchers.
