# Shared account ID bank and execution coordination

**Goal:** Separate each host's lots and pending orders within one destination account, with durable IDs and cash/unit reservations, then integrate the Windows receiver. Retire reconciled empty IDs from the active bank without losing replay protection.

**Architecture:** One SQLite bank per installation, immutable scope=(broker,account,environment), numeric display ID and permanent source-trade identity, distinct deterministic client-order IDs, BEGIN IMMEDIATE reservations, per-account execution locks. Buy reservations consume account shadow capacity before POST; timeouts retain reservations. Verified cumulative fills own units by host/trade. Exits reserve only that ID's units; terminal partial cancellations retain filled holdings. Sold/invalid empty IDs leave the active table; permanent history/tombstones reject replay. No operator action clears unknown orders. Account inventory discrepancies block new entries without transferring ownership.
